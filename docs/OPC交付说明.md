# OPC 一人公司系统 · 交付说明

> 一人公司（One Person Company）的**设计师接单撮合台账**  
> 技术底座：CodexFDE 工作台（`E:\drill-system`）  
> 设计规格：`docs/opc_spec.md`

---

## 一、这是什么

 给**一个人**用的零工平台运营系统：把散落在微信、表格、记忆里的  
**订单、设计师、交付物、佣金、结算**收敛到一个台账里，  
让「每笔钱从哪来、到哪去、谁该拿多少、证据是什么」随时可查、可交接、可审计。

它不是大平台的复刻。大平台要做权限体系、菜单管理、多租户；  
一人公司用不上那些，做了反而是负担。这个系统只做**台账**。

---

## 二、它解决什么问题

一个人在零工平台上接单，最容易乱的是这四件事：

| 乱在哪            | 系统怎么管                                                   |
| -------------- | ------------------------------------------------------- |
| 「这单当时到底要求了什么？」 | 需求单**六段式**（目标/范围/非目标/约束/验收标准/完成定义），创建时存**快照**，后来改需求不改快照 |
| 「他做的到底合不合格？」   | 交付**证据链**：初稿不合格(红) → 返工(改) → 终稿合格(绿)，且**必须同一条验收命令**     |
| 「这钱能不能给？」      | **结算门禁**四道：前置已验收 / 证据链完整 / 责任分离 / 已具名验收。程序**永不代签**      |
| 「返工几轮了？还值得改吗？」 | **有界返工回路**：最多 3 轮；连续两轮原因完全相同就停手转人工                      |

## 四、订单状态机

```
待派单 → 已派单 → 已接单 → 初稿制作中 → 终稿制作中 → 待验收 → 已交付 → 待结算 → 已结算
                                      ↑___________ 返工（自环）_____________↓
```

- 跳阶段一律拒绝
- `初稿制作中` 的**自环**就是「返工」
- 可去状态由后端 `GET /api/opc/meta` 下发，前端不抄流转表

## 五、分账口径

照搬内部总后台的真实结构（设计师佣金 / HR 佣金 / 品控佣金 / 主管奖金 / 中控金额），  
但**比例只从 `opc_split_rules` 表读**，代码里不写死任何比例。

默认种子：

| 口径    | 比例  | 说明                       |
| ----- | --- | ------------------------ |
| 设计师佣金 | 70% | 接单佣金                     |
| HR 佣金 | 10% |                          |
| 品控佣金  | 8%  |                          |
| 主管奖金  | 2%  | 可切到「按奖金基数」算              |
| 中控金额  | 5%  | 公司留存；比例总和不足 100% 时余数也归这里 |

**金额一律 Decimal**，份额合计**绝不超过总额**（超出部分强制归入中控并报 issue）。

## 七、AI 推荐与降级

`GET /api/opc/match/recommend` 先试大模型（千问 / DeepSeek / 豆包，走 FDE 已有的  
`llm_client`），**任何异常都吞掉并降级**到本地关键词相关度排序。

**候选池绝不返回空数组** —— 空数组对界面毫无意义。

中文分词按「量词 + 方位词」切（「元以内的女士连衣裙」不会被整块当一个词），  
匹配走 **2 字片段重叠**（「女士连衣裙」能命中标签里的「连衣裙」）。

## 十、刻意不做的事

1. **不做移动端 App** —— 使用场景是「一个人在电脑前处理今天的事」
2. **不做在线支付/提现** —— 结算端只做记录与对账，实际打款走支付宝手工操作，  
   系统记「已打款 + 时间 + 备注」方便月底对账
3. **不做 IM/推送** —— 微信自己看，系统只在页面内提示
4. **不替代总后台/结算端** —— 这是自用轻量台账，不追求覆盖大平台全部功能
5. **不做多租户** —— 只有一个人用
6. **不做抓取** —— 订单来源是人工录入，不爬

## 十一、踩过的坑（已在 AGENTS.md 记录）

1. AntD 6 移除了 `Modal` 的 `extra` 属性
2. AntD 6 的 `TablePaginationConfig` 没有 `sizeChanger`
3. 中文分词不能只按标点切，「元以内的女士连衣裙」会整块当一个词
4. 返工回路的停止条件必须**先于**「等待复验」判断，否则上限信号被吞掉
5. `parse_spec` 要跳过文档标题（H1）
6. 登录页填值不能用 `type !== 'password'` 找账号框（Segmented 也是 radio）
7. 状态机的「可去状态」由后端下发，前端抄一份就会「前端能点、后端拒绝」
